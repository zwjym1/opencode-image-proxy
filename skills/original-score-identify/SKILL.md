# 识别参考片的同一首原伴奏

目标只有一个：找出**同一首原曲、同一录音版本**的伴奏或平台曲库条目。  
不是另挑一首风格接近的歌，也不是把作者「原声」或成片混音直接当 BGM。

## 思路

1. **作者原声不等于曲名。** 标题形如「@某作者创作的原声」只说明这是上传原声。`is_matched_metadata=false` 时尤其不能写成已识别的歌名。
2. **只追这一首。** 没有歌名候选时，不得改搜替代曲，也不得用风格词或检索词交差。公开检索这一段自己的歌词、作者或二创名不算换歌。同一首仍可继续取样、分轨和送检。
3. **查库不等于定名。** 只要出现候选，就可以去曲库取试听和条目，不必先凑满两段命中。定名则必须同时有独立证据和同录音试听。
4. **混音和分轨都不是母带。** 含口播的成片混音不能当制作 BGM。`no_vocals` 是模型估计，也不能当最终伴奏。二创歌声和旁白会一起进 `vocals`。`no_vocals` 很弱只说明这条伴奏估计能量低，不代表没有配乐。
5. **普通识曲覆盖不了二创。** 参考 BGM 可能是哈基米、南北绿豆这一类二创。这两个名字只是这类材料的例子，不是已经确认的歌名。普通指纹无匹配之后，还要把二创歌词或音节、原旋律、二创标题分开追。
6. **不能听音就先声明。** 没有实际听音条件时，写明不能听音。不猜歌词、音节或旋律，也不用想象代替同录音试听。
7. **三个结论不能互顶。** 二创版本、原曲、同录音素材分开写。当前没有已确认歌名，不声称成功。
8. **识曲只走正式入口。** 允许正式的官方识曲工具，以及用户能自己打开的公开网页。正常验证码或登录按该入口自己的流程完成。不得绕过，不得调用未公开或逆向接口，不要用 shazamio 一类非官方客户端去打私有识曲 API。
9. **当次页面不是长期规格。** 功能、费用、广告、次数、文件大小、是否要账号、分析多长，都只记当次打开时所见。不要把这些写成技能里的固定事实。
10. **两种失败分开记。** `service_error` 是故障或没提交成功；`no_match` 是正常结束但没有匹配。无匹配不是曲名，也不能改写成已识别。

## 验证边界

下表是这套方法核对到哪里，不是某一条片子的验证记录。不得据此声称端到端已经跑通。

| 环节 | 核对情况 |
|---|---|
| 混音样本送去识曲 | 已尝试 |
| 本机用 Demucs 官方权重 `htdemucs` 分轨 | 分轨成功 |
| 分轨结果的中段送 AudioTag 与 AHA | 两处都正常返回，而且都是无匹配 |
| 可靠曲名 | 没有。正常返回的无匹配不是曲名 |
| 平台曲库中的同录音版本 | 尚未核对 |
| 二创歌词或音节、原旋律、二创标题 | 尚未分开核实出歌名。普通识曲的无匹配没有把这一支做完 |
| 从参考片到可制作使用的同曲伴奏 | 未跑通 |

已核对的只有这三件事：混音样本可以拿去试；官方 `htdemucs` 能在本地分出音轨；分轨中段能在 AudioTag 和 AHA 上走完一次正常识别，并且那一次的结果是无匹配。曲名、二创版本、原曲、同版本曲库条目、可制作使用的干净伴奏，都不在已核对范围内。分轨成功不能写成已经找到伴奏。那次无匹配也不能写成没有配乐，或写成二创已经排除。

本技能没有听音结论。不能听音时必须在当次记录里声明，不能把猜的歌词或旋律写进来。

以后的任务按当次结果重记。不得援引本技能补上一个曲名。没有同一首的歌名候选时，不得换成另一首歌。某次任务的路径、媒体 ID 和文件清单不要写回本技能。当前仍无已确认歌名，不声称成功。

## 步骤

1. **元数据**  
   读取参考片的公开音乐字段：标题、作者、音乐 ID、是否原声、`is_commerce_music`、`is_pgc`、音乐页、试听直链。先记下「原声 / 曲库命名曲 / 未知」。原声标题到此为止，不当作曲名。  
   试听直链为空就记 `observed_empty`（字段状态，不是曲名结论），不要为了取音去打内部接口。`is_commerce_music=false` 只表示没有标成曲库可商用，既不是绝对禁令，也不是已授权；标成可商用也不等于写明了出站范围。  
   评论或转写里写明了歌名和作者的，可以当作书面线索并标明来源；它最多充当定名所需的书面证据，不能代替同录音试听。含糊说法、识别错误的句子，不算证据。

2. **切三个代表片段**  
   从头、中、尾各取一段约 20–30 秒，保存为常见音频格式。记录源时间码、时长和做了什么处理（剪切、响度归一可以做）。可用响度或静音测量挑选口播相对少的窗口。只要还含口播，就写明「混音样本，不是纯音乐」。整段都是口播铺底时，写「无纯音乐段」，不要编出一个纯音乐窗口。  
   这是取样长度，不是某个网站的固定上传规格。

3. **识曲（先混音）**  
   用正式的官方识曲工具，或公开网页，把片段送进去。下面两处只是方法核对里已经用过的公开页，不是唯一入口：
   - https://aha-music.com/upload 或 https://aha-music.com/zh/upload
   - https://audiotag.info/ （说明见 https://www.audiotag.info/faq ）

   该页或该工具当前写的格式、大小、时长、费用、次数、广告和账号要求，只记在当次记录里。页面上的旧说法不要抄进结论当长期事实。工具若要求只提交其中一段，或只分析开头，按当次说明执行。  
   逐段记录：哪个入口、有没有验证码或登录、实际提交的时间窗口、返回的歌名 / 作者 / 专辑 / 链接，或页面原文。
   - 报错、中断、无法提交：`service_error`。可以换一个允许的入口或稍后重试。不要写成「库中无此曲」。
   - 停在正常的验证码或登录，识别还没完成：`captcha_or_login`。按页面正常完成，不要绕过。
   - 正常结束但没有结果，或明确无匹配：`no_match`。口播很重时，这是可能出现的结果，不是流程写错。无匹配不排除二创，也不等于没有配乐。工具若返回了歌名，先按原文记成候选，并标明它更像旋律命中还是标题命中；不要直接写成二创名或同录音。

4. **混音没有歌名候选时，才做分轨辅助**  
   先看本机是否已有 Demucs，以及官方 `htdemucs` 权重是否已在本地。没有 Demucs 时不要改装别的分离模型。缺的只补这一份官方权重，并核对体积；不要下载其他大模型。  
   官方文件：https://dl.fbaipublicfiles.com/demucs/hybrid_transformer/955717e8-8726e21a.th  
   体积 84141911 字节。文件名中的 `8726e21a` 是该发布文件使用的 SHA256 前 8 位。  
   本地 repo 使用官方包里的 `htdemucs.yaml` 加上这个权重。命令里的路径按当次环境填写：

   ```bash
   demucs -n htdemucs --repo /path/to/htdemucs_repo -d cpu \
     --two-stems vocals --mp3 --clip-mode rescale \
     -o /path/to/separation_out /path/to/clip.mp3
   ```

   无 GPU 时使用 `-d cpu`。产出是 `vocals` 和 `no_vocals`。二创歌声和旁白会一同进 `vocals`，不要把 `vocals` 当成纯净人声，也不要把它整段扔掉。`no_vocals` 很弱，只说明这条伴奏估计的能量低，不代表成片没有配乐。混音、`vocals`、`no_vocals` 都要单独查看；能量和时长都记下。能送检的再送去正式识曲入口。不能只识别伴奏轨就结束。按当次返回记录，不要套用上一次的结论。  
   方法核对里，官方权重的本地分轨是成功的；送去 AudioTag 和 AHA 的是分轨**中段**，两处都正常返回，结果都是 `no_match`。那一次的无匹配不是曲名，也不是「没有配乐」或「二创已排除」。电平偏低或残留口播都可能造成无匹配，但原因没有核成事实，不要拿来改写返回结果。以后的片段仍要单独送检，不得因为这一次无匹配就跳过识曲。任何情况下都不要把 `no_vocals` 当作母带或最终 BGM。

5. **普通识曲没有已确认歌名时，走二创分支**  
   这一支追的仍是同一段参考，不是去找一首风格接近的替代歌。不等伴奏轨先识别成功才开始。哈基米、南北绿豆只说明「可能是这类二创」，不能写成当次结论。  
   没有实际听音条件时，这一支开头就写「不能听音」。此后只采用页面、字幕、评论或其他书面来源里已经写明的字，并保留出处。写不出来的歌词、音节和旋律就记「未取得」，不要猜。  
   三条线分开记，不要并成一个歌名：
   - **二创歌词或音节：** 实际听到的，或书面来源写明的字和音节。不能听音、又没有书面歌词时，这一条就是未取得。
   - **原旋律：** 和歌词分开。普通识曲命中的歌名先放在这一条，作为旋律候选。它还不是二创标题，也还不是同录音。
   - **二创标题：** 用公开检索去核对歌词、作者、二创名。要找的是把歌词或音节、二创标题、原曲名对应起来的可复核材料（页面原文、作者说明、同一处写明的原曲名）。检索词、联想词和风格印象都不是证据。没有这种对应材料，就保持无线索。

   变调或变速：只有已有依据说明参考相对某条候选被移了调或改了速度，才按那个依据做标准恢复，然后再送识曲或做对照。没有依据就不要变速，也不要变调。恢复后的结果仍是候选，不是定名。  
   这一支即使得出某个二创名或某首疑似原曲，也只是对应那一条线的候选。不能用它声称整首歌已经识别成功。方法核对目前没有已确认歌名。

6. **有候选就查库，不要等两段都命中**  
   返回里写明了歌名，就可以拿这个候选去查试听和条目；作者有则一并使用。只有风格描述、没有歌名，不算候选。两段独立结果如果一致，用来交叉验证：它能加强把握，但不是打开曲库的前提，也不能代替同录音试听。  
   没有候选（识曲正常结束仍无歌名，或只有原声标题）时，不要查「也能用」的别的歌，也不要把这一步记成 `library_miss`。查到的条目要写明它对应二创版本、原曲候选，还是同录音；名字像，不能把另一条线写成已核。  
   需要查库时，下面几处分开查，不要把一边的结果抄到另一边：
   - 抖音音乐 / 曲库
   - B 站音乐或素材
   - 剪映素材库

   CapCut 是另一项服务。若也去查，单独记录。剪映里的条目和授权不自动适用于 CapCut，CapCut 的条目和授权也不自动适用于剪映。记录搜索词、条目链接或 ID、展示名是否与候选一致、是原曲还是翻唱或剪辑版、页面上写明的授权或「可商用」文字、检索时间。页面没写的范围不要补。

7. **定名**  
   二创版本、原曲、同录音素材是三件分开的事。一件写成 `identified`，不能冒充另一件。  
   每一件都要两样齐，才能对**那一件**使用 `identified`：
   - **独立证据：** 识曲工具或公开页、曲库或发行条目、或其他书面来源，写明了这一件的名称和作者，以及它对应的是二创版本、原曲，还是同录音素材。风格像、旋律像、搜索时试探的词，都不是独立证据。评论或转写里的句子只有在写明名称和作者时才算书面来源，并要保留出处。
   - **同录音试听：** 把候选录音和参考片里的同一段音乐对照着听，确认是同一录音。同曲的翻唱、重编、二创填词、只是速度接近，都不是同一录音。不能听音的人做不了这一条，必须声明，不能用猜测代替，因此也不能自己写成 `identified`。

   只有一段命中、还没有同录音试听：保持 `partial`，并写明候选属于哪一条线。候选可以留着，也可以继续查库，但不定名。只拿到二创标题时，原曲和同录音仍是未确认。只拿到原旋律候选时，二创版本和同录音仍是未确认。  
   不同片段或不同版本互相矛盾：`conflict`，不要挑一个来交差。  
   试听对不上同一录音：这个候选不成立，不得改用它充当原伴奏。  
   不得只凭旋律相似定名。

8. **能不能用于制作**  
   优先使用素材库里授权文字已经写明的官方条目或干净伴奏。只有授权允许、并且确认没有他人口播时，才能用于制作。  
   可用范围只抄条目或授权文件上的文字（例如仅限某个 App、能否拿到 App 外）。没写明就标 `license_unknown`，不得凭曲名推断可商用或可跨平台。  
   还没有可合法使用的干净伴奏时，标 `clean_audio_unavailable`，并且不要把混音样本、他人原声或分轨估计当 BGM。

9. **收束**  
   结论使用下一节的一个主状态，并留下当次证据。要声称原伴奏任务成功，必须原曲或同录音素材这一条已经 `identified`，并且同版本曲库已经查过（查到同版本，或明确记成 `library_miss`）。只定出二创版本不算成功。授权没写明、或还没有干净伴奏时，仍然不能当 BGM。方法核对没有已确认歌名，也没有查过同版本曲库，所以不能声称成功，也不能声称端到端已跑通。

## 结束状态

写结论时只标一个主状态，其余事实写在证据里。选择规则如下，不要按表格从上到下碰见的第一项就停。

| 状态 | 含义 |
|---|---|
| `captcha_or_login` | 停在正常验证或登录，识别还没完成 |
| `service_error` | 页面或工具故障、中断、无法提交。不是无匹配 |
| `no_match` | 识曲正常结束，但没有匹配。方法核对里的分轨中段就是这个结果 |
| `speech_masked` | 口播过重，结果不可靠，需要换窗口或分轨后再试。没有候选时不要改去搜别的歌 |
| `metadata_only` | 只有平台原声或音乐字段，识曲还没有给出曲名。已经得到 `no_match` 时不要退回这一项 |
| `partial` | 已有候选，但独立证据和同录音试听还没有齐。一段命中而尚未试听，或只确认了二创、原曲、同录音其中一条线的线索时，用这项，并写明是哪一条 |
| `conflict` | 片段之间或版本之间互相矛盾 |
| `identified` | 某一条结论同时具备独立证据和同录音试听。必须写明定的是二创版本、原曲，还是同录音素材。三者不能互相顶替 |
| `library_miss` | 对应的那条曲名已经成立，库中没有同录音版本。没有候选，或只定了另一条线时，不要用这项 |
| `license_unknown` | 见到条目，但授权或出站范围没有写明 |
| `clean_audio_unavailable` | 还没有可合法使用的干净伴奏 |

还没定名时，按实际卡住的位置选一个，不要用靠前的空结果盖住已有候选：

- 候选互相矛盾：`conflict`
- 某一条线已有名称线索，但这一条的独立证据和同录音试听还没齐：`partial`，并写明是哪一条。另外两条未成立，不能把这一条写成它们的 `identified`。同一任务里其他片段无匹配，不把主状态改回 `no_match`
- 还没有候选，并且停在验证码或登录：`captcha_or_login`
- 还没有候选，并且入口故障或没提交成功：`service_error`
- 正常结束且没有任何歌名候选：`no_match`。口播很重只写进证据；只有在样本根本不能当一次有效送检、还要换窗口或分轨时，才改标 `speech_masked`。二创分支还没做完时可以维持 `no_match`，但要写明二创未完成，不能把该状态说成任务结束
- 只有平台原声或音乐字段，识曲还没有结论：`metadata_only`

定名成立之后，证据里写明 `identified` 的是二创版本、原曲，还是同录音素材。未成立的另外两条保持未确认，不能跟着写成已定。只定出二创版本、而原曲和同录音都还没成立时，原伴奏任务的主状态保持 `partial`，证据里写明二创版本这一条已经 `identified`。原曲或同录音已定、但使用被挡住时，主状态改标最先挡住的一项：库中没有同版本用 `library_miss`；见到条目但授权或出站范围没写明用 `license_unknown`；授权范围内仍没有干净伴奏用 `clean_audio_unavailable`。只定出二创版本时，不要用这三项表示原曲已核。`identified` 不表示可以当 BGM，也不表示另外两条结论成立。

方法核对里，混音样本只是试过，没有得出曲名；分轨中段在 AudioTag 和 AHA 上的正常返回是 `no_match`。二创三条线没有核实出歌名。整次核对没有已确认歌名，平台库同版本也没有查，主状态停在 `no_match`，不是 `identified`，也不是 `library_miss`。不声称成功。

## 限制

- 没有可复核的对应材料时，不换一首「风格接近」的歌，也不把检索词写成已经选定的原曲。公开检索歌词、作者、二创名是在追同一段，不是换歌。
- 不把普通识曲的无匹配写成二创已排除，也不把 `no_vocals` 能量低写成没有配乐。不能只识别伴奏轨。
- 不在没有听音能力时猜歌词、音节或旋律。先声明不能听音。
- 不把二创版本、原曲、同录音素材写成同一个结论。只定出二创版本不算原伴奏任务成功。
- 没有依据就不变速、不变调。
- 不把分轨估计、成片混音或他人原声当作最终 BGM。
- 不绕过验证码或登录，不为取音、识曲去用内部或逆向接口。
- 不把某次页面上的功能或费用描述写成长期事实。
- 不把剪映条目和 CapCut 条目当成同一条授权。
- 不要求两段都命中才去查库。也不在缺少独立证据或缺少同录音试听时定名。
- 没有已确认歌名，或同版本曲库还没查过时，不宣称成功。方法核对里歌名仍未确认，这两项都还没有成立。
